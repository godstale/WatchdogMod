# Watch Dog

Claude Code 프롬프트 바로 위에 떠 있는 **실시간 관제 패널**입니다.
메인 에이전트와 서브 에이전트가 지금 무엇을 하는지 보여 줄 뿐 아니라, **작업이 도는 도중에** 요청을 끼워 넣고,
에이전트 하나만 골라 일시정지·재개하고, 정리 보고를 받은 뒤 안전하게 멈출 수 있습니다.

```
╭─────────────────────────────────────────────────────────────────────────────────────────────────╮
│  ██▄▄▄▄▄▄██      WATCH DOG  sonnet5.5/high  ⠋ Working 02:30  ✉ 1                                │
│  ██████████      ▶ ⚙ Edit auth.ts  ███████░░░ 7/10 70%  “refactor auth”                         │
│   ▀██████▀ ▄     ├─ #1 ● explore find auth usages  haiku5.5/low  tools 12  ⚙ Grep  00:50        │
│   ▄▄▀██▀▄▄▀      └─ #2 ● general-purpose write tests  sonnet5.5/medium  tools 4  00:12  │ ✓ 1   │
│                  ctx 24%, 239k/1.0M │ limit 5h(9%), 7d(1%), reset(3h 12m) │ Used $3.23          │
╰─────────────────────────────────────────────────────────────────────────────────────────────────╯
```

## 왜 Watch Dog인가

긴 작업을 맡기면 Claude Code 는 끝날 때까지 기다리는 수밖에 없는 경우가 많습니다.
Watch Dog 은 그 시간을 **보고, 말하고, 멈출 수 있는 시간**으로 바꿉니다.

* **상태 보기** — 메인 작업의 진행률, 지금 실행 중인 도구, 서브 에이전트마다의 상태·모델·도구 사용 수를 프롬프트 위에 상시 표시합니다.
* **실행 중 요청 끼워 넣기** — `/wd say` 로 돌아가는 작업에 새 지시를 넣습니다. 진행 중인 도구 호출이 끝나면 모델이 다음 요청부터 바로 읽습니다. 작업을 끊고 처음부터 다시 시킬 필요가 없습니다.
* **에이전트별 제어** — 번호로 서브 에이전트를 하나씩 고릅니다. `/wd say #2`, `/wd pause #2`, `/wd stop #2`. 나머지 에이전트는 그대로 달립니다.
* **일시정지 · 재개** — `/wd pause` 는 다음 도구 호출 앞에서 멈춥니다. 멈춘 동안에도 요청을 넣을 수 있고, `/wd resume` 하면 모델이 새 요청을 읽고 계획을 다시 세웁니다.
* **정리 후 중단** — `/wd stop` 은 ESC 처럼 작업을 끊지 않습니다. 진행 중인 도구 호출은 끝내고, 새 작업만 막은 뒤 "끝난 일 / 남은 일 / 미완료 상태"를 보고하고 종료합니다.
* **사람이 필요할 때 알림** — 권한 확인이나 질문을 기다리면 강아지가 `?` 로 알리고 데스크톱 알림을 띄웁니다. 사용량 한도 임박, 컨텍스트 90% 이상, 서브 에이전트 실패도 알려 줍니다.
* **되돌아보기** — `/wd-log` 로 메인과 서브 에이전트가 최근에 한 도구 호출을 봅니다.
* **모델을 부르지 않는 명령** — `/wd-help`, `/wd-log` 는 토큰을 쓰지 않고, 작업 도중에도 바로 실행됩니다.

```
/wd say 테스트도 같이 돌려줘          실행 중인 작업에 요청 끼워 넣기
/wd say #2 범위를 src/auth 로 줄여     2번 서브 에이전트에게만 전달
/wd pause #2  →  /wd resume #2       2번만 멈췄다가 다시 달리기
/wd stop                             정리 보고 후 중단
/wd-log #2                           2번이 최근에 한 도구 호출
```

## 설치

Claude Code 2.1.275 이상에서:

```
/plugin install watchdog --marketplace godstale/WatchdogMod
```

설치 후 `/wd` 를 입력하면 도움말이 나옵니다. 대시보드를 바로 시험해 보려면 아래 `/wd-test` 항목을 참고하세요.

## 화면 구성 (3~7줄: 테두리 2줄 + 내용 1~5줄)

| 그룹 | 내용 |
| --- | --- |
| 상태 (첫 줄) | `WATCH DOG` 옆에 **메인 모델/effort**, 이어서 작업 중/대기/일시정지/중단 처리 중/입력 대기, 경고, 경과 시간, 끼워 넣은 요청 수 |
| 작업 | 현재 프롬프트, 진행률(TodoWrite 기준 `done/total`, 없으면 step·툴 수), 지금 실행 중인 툴 |
| 에이전트 | 활성 에이전트를 먼저(번호, 상태 — `●` 실행 `⏸` 일시정지 `■` 정리 중 —, 타입, 모델/effort, 툴 수·진행률, 현재 툴, 경과), 끝난 것은 `✓ n ✗ n` 으로 요약 |
| 툴 | 툴별 사용 횟수 상위, 실행 중인 툴 |
| 사용량 | 컨텍스트 사용률·토큰, 5h/7d usage limit(리셋까지 남은 시간), 세션 비용 |

내용이 많으면 우선순위(상태 > 작업 > 사용량 > 에이전트 > 툴 > 추가 에이전트)로 줄이고,
에이전트가 줄 수보다 많으면 나머지를 한 줄로 압축합니다. 대기(Idle) 중에는 3줄(총 5줄)로 줄어듭니다.
강아지는 하프 블록(`▀▄`)과 24비트 색으로 그린 정면 픽셀아트(15칸 폭: 강아지 12칸 + 오른쪽 표지 3칸)입니다. 상태마다 그림이 다릅니다 — 아래 [상태와 픽셀아트](#상태와-픽셀아트) 참고. 24비트 색을 지원하지 않는 터미널에서는 색이 다르게 보일 수 있습니다.

## `/wd` 명령

사용자가 직접 입력한 명령(`composer`/`bridge`)만 받으므로 모델·SDK·예약 작업·다른 플러그인이 호출할 수 없습니다.
코드 입력은 없습니다.

```
/wd                             도움말
/wd say 테스트도 같이 돌려줘          실행 중인 작업에 요청 끼워 넣기
/wd say #2 범위를 src/auth 로 줄여     2번 서브 에이전트에게 전달
/wd pause                       작업 일시정지 (다음 도구 호출 앞에서 대기)
/wd pause main|agents|#2        대상 지정
/wd resume                      재개 (대상 지정 가능)
/wd stop                        전체를 정리 후 중단
/wd stop main|agents|#2         대상 지정
```

읽기 전용 명령 (작업 중에도 바로 실행됩니다):

```
/wd-log                     메인 + 서브 에이전트가 최근에 한 도구 호출 5개씩
/wd-log main 10             메인만, 10개 (최대 20)
/wd-log #2                  2번 에이전트만
/wd-help 작업을 잠깐 멈추고 싶어    요청에 맞는 사용법과 복사해서 쓸 명령을 알려줌 (한국어/영어)
```

* **끼워 넣기**: `$.session.append` 로 대화에 사용자 역할 메시지를 추가합니다. 진행 중인 도구 호출은 그대로 끝나고,
  모델은 다음 요청부터 이 메시지를 읽습니다. 실행 중인 작업이 없으면 일반 프롬프트로 제출합니다.
* **일시정지 / 재개**: `pause` 는 진행 중인 도구 호출은 그대로 끝내고, 그 루프의 **다음 도구 호출 앞에서** 기다리게 합니다
  (모델 요청 하나는 더 나갈 수 있습니다). 헤더에 `⏸ Paused main, #2 00:12` 가 뜨고 강아지는 앉은 자세가 됩니다.
  멈춘 동안에도 `say` 로 요청을 끼워 넣을 수 있고, 그러면 `resume` 때 붙잡아 둔 호출을 **한 번 거부**해서
  모델이 새 요청을 읽고 계획을 다시 세우게 합니다. `stop` 은 일시정지도 풀어서 정리할 수 있게 합니다.
  Esc 로 턴을 끊으면 대기도 끝납니다.
* **정리 후 중단**: ESC 처럼 즉시 끊지 않습니다. 이미 실행 중인 도구 호출은 끝까지 두고, 이후 새 도구 호출
  (Read/Grep/Glob/Todo 갱신 제외)은 거부하며, 모델에게 "새 작업 금지, 완료/남은 일/미완료 상태를 보고하고 종료"
  하라는 메시지를 넣습니다. 45초가 지나도 안 끝나면 토스트로 Esc 를 안내합니다.

## 상태와 픽셀아트

| 상태 | 언제 | 그림 | 알림 |
| --- | --- | --- | --- |
| **Idle** | 아무것도 안 하는 중 | 정지 그림 (눈 감은 얼굴, 애니메이션 없음) | — |
| **Working** | 턴/서브 에이전트 실행 중 | 헐떡이고, 꼬리 흔들고, 발 구르고, 귀 펄럭이고, 깜빡임 (0.5초 4프레임) | — |
| **Stop** | `/wd stop` 처리 중, 또는 `/wd pause` 로 일시정지 중 (헤더 문구가 다름) | 얌전히 앉아 주황 일시정지 막대(`‖`)가 깜빡임, 느린 깜빡임 | — |
| **Warning** | 5h/7d 한도 또는 컨텍스트 90% 이상, 서브 에이전트 실패(60초 이내) | 눈썹 내리고 짖음, 빨간 `!` 깜빡임, 목줄 점멸 | 데스크톱 알림 (경고마다 한 번, 풀렸다가 다시 생기면 또) |
| **Input** | 권한 확인·`AskUserQuestion` 등 사람의 답을 기다리는 중 | 귀 쫑긋, 꼬리 흔들고, 파란 `?` 가 통통 뜀 | 데스크톱 알림 (호출마다 한 번) |

우선순위: Input > Stop > Warning > Working > Idle. 헤더에는 `? Waiting for you: Bash`, `⚠ 5h limit 93%`
처럼 이유가 함께 나오고, 경고 중에도 `Working` 시간은 그대로 보입니다.
공간이 모자라면 `full`(4줄) → `head`(3줄) → `mini`(2줄) 순으로 줄고, 그림이 들어갈 자리가 없으면 그림 없이 글만 보입니다. 어느 크기에서도 상태별 그림이 다릅니다.

## 데스크톱 알림

Warning / Input 이 되면 OS 알림을 띄웁니다.

* **Windows**: 토스트 (`powershell.exe` 의 WinRT, 알림 문구는 환경 변수로 넘겨 인용 문제 없음)
* **macOS**: `osascript` 의 `display notification`
* 그 외 OS 이거나 위 명령이 실패하면 터미널 자체 알림 채널(`$.ui.notify`: iTerm2·kitty·ghostty·bell)로 대신 보냅니다.

모드 API 의 `$.ui.notify` 는 터미널 알림 시퀀스만 보내서 Windows Terminal 등에서는 아무것도 뜨지 않기 때문에,
OS 명령을 직접 부릅니다. Windows 의 집중 지원/방해 금지 모드나 macOS 의 알림 설정이 막으면 배너는 보이지 않습니다.

## `/wd-test` — 대시보드 테스트 (토큰 최소)

haiku 로 `sleep 5` 만 반복하는 서브 에이전트를 띄워 대시보드와 `/wd` 를 시험합니다.
(플러그인 명령이라 `/watchdog:wd-test` 로 보일 수 있습니다.)
`pause`·`resume`·`say`·`stop` 은 `stop` 시나리오로 시험하세요.

| 인자 | 내용 |
| --- | --- |
| `basic` (기본) | 길이가 다른 에이전트 3개를 동시에, 나중에 1개를 더 — 시작/종료 시점이 어긋나는 상황 |
| `many` | 에이전트 6개 동시 — 한 줄 압축 표시 확인 |
| `stop` | 에이전트 2개가 약 100초씩 — `/wd stop agents`, `stop #1`, `stop main`, `say #2 …` 시험용 |
| `solo` | 서브 에이전트 없이 메인만 sleep 10회 — 메인 루프 표시/중단 |
| `input` | sleep 후 `AskUserQuestion` 을 띄움 — Input 상태(`?` 강아지)와 데스크톱 알림 확인 |

Warning 은 한도/컨텍스트가 90% 를 넘어야 해서 `/wd-test` 로 만들 수 없습니다. 테스트(`claude plugin test .`)가 판정과 그림을 확인합니다.

## 한계 (직접 확인할 것)

* 창은 입력창 **바로 위** 띠(`AbovePrompt`)에 그려집니다. 모드 API 에는 입력창 아래에 자유 영역이 없습니다.
* 진행률은 모델이 `TodoWrite` 로 만든 목록 기준입니다. 목록이 없으면 비율 대신 step/툴 수를 보여줍니다.
* 서브 에이전트의 현재 작업·모델/effort 는 해당 에이전트의 첫 도구 호출/모델 요청 이후부터 보입니다.
* 정리 후 중단은 모델의 협조(보고 후 종료)를 전제로 하며, 실행 중인 Bash 등은 끝날 때까지 기다립니다.
* `/wd` 는 코드 없이 열려 있습니다. 보안 경계는 명령을 받는 출처(`composer`/`bridge`)에서만 나오며, 원격 bridge 로 보낸 메시지는 원래 프롬프트와 같은 권한을 가집니다.
